# Cloud Nine Playback Bug Analysis & Fix Blueprint

## Executive Summary

When attempting to play tracks from the autogenerated **"Cloud Nine"** smart playlist (or any cloud-only playlist), ExoPlayer rapidly skips through every song in the queue before halting playback. This report provides a detailed technical breakdown of the root causes across the data, playback, and extraction layers, followed by an architectural blueprint for a complete resolution.

---

## Part 1: The Root Cause Analysis

### 1.1 Data Layer & Playlist Population

* **Playlist Resolution**: "Cloud Nine" is a smart playlist managed by `MusicRepository.kt`. It dynamically queries Room for all songs where `isDownloaded == false` (`notDownloadedSongs` Flow via `SongDao.getNotDownloadedSongs()`).
* **Entity Properties**: A cloud-only `Song` entry in Room contains:
  * `isDownloaded = false`
  * `youtubeId = "<YouTube Video ID>"` (e.g., `"dQw4w9WgXcQ"`)
  * `mediaUri = "https://www.youtube.com/watch?v=<youtubeId>"`
* **Absence of Separate URI Fields**: The `Song` data class (`app/src/main/java/com/example/tgmusicai/data/local/entity/Song.kt`) has no `localUri` or `fileUri` properties. It contains a single `mediaUri` string field. For un-downloaded cloud tracks, `mediaUri` stores the raw YouTube web watch URL rather than a direct audio CDN stream URL or local file path.

### 1.2 Queue Construction & MediaItem Generation

When the user taps **"Play All"** or selects a track in `PlaylistDetailScreen.kt`:
1. `PlaylistDetailScreen.kt` invokes `PlayerViewModel.playQueue(songs, startIndex)`.
2. `PlayerViewModel` delegates to `MediaControllerManager.playQueue(queue, startIndex)`.
3. `MediaControllerManager` executes `playQueueProgressively(queue, startIndex, onStarted)`:
   * It pauses current playback and sets `_isResolving.value = true`.
   * It attempts to resolve **only the starting song** (`queue[startIndex]`) synchronously using `resolveSongForPlayback(song)`.
   * It constructs `initialQueue`, in which index `startIndex` has the resolved stream URL (if extraction succeeded), but **all other songs in `initialQueue` (indices `!= startIndex`) retain their raw YouTube watch URLs** (`https://www.youtube.com/watch?v=...`).
   * `playInternal(initialQueue, startIndex)` converts all items in `initialQueue` into Media3 `MediaItem` instances via `buildMediaItem(song)`.
   * `MediaItem` objects are built with `.setUri(Uri.parse(song.mediaUri))`. As a result, ExoPlayer's timeline receives `MediaItem`s whose playback URIs are raw web watch URLs for all remaining queue items.
   * `resolveRemainingInBackground(initialQueue, startIndex)` is launched as a background coroutine to resolve remaining songs asynchronously.

### 1.3 ExoPlayer Failure Mode on Raw Web URLs

When ExoPlayer attempts to load a `MediaItem` whose URI is `https://www.youtube.com/watch?v=...`:
1. `DefaultHttpDataSource` opens an HTTP GET connection to YouTube.
2. YouTube returns an HTML web page (`HTTP 200 OK` with `Content-Type: text/html`).
3. ExoPlayer's media extractors (`DefaultExtractorsFactory`: MP3, AAC, MP4, WebM, TS) attempt to parse the response body as audio stream bytes.
4. The extractors fail to find valid audio container headers in the HTML content, throwing a `PlaybackException` (wrapping `UnrecognizedInputFormatException` or `ParserException`).

### 1.4 The Error Cascade & Rapid Skip Loop

In `PlaybackService.kt`, ExoPlayer's `Player.Listener` catches the `PlaybackException` in `onPlayerError`:

```kotlin
override fun onPlayerError(error: androidx.media3.common.PlaybackException) {
    android.util.Log.e("PlaybackService", "Playback error encountered: ${error.message}", error)
    consecutivePlaybackErrors++
    if (consecutivePlaybackErrors <= MAX_CONSECUTIVE_PLAYBACK_ERRORS && hasNextMediaItem()) {
        seekToNextMediaItem()
        prepare()
        play()
    } else {
        android.util.Log.w("PlaybackService", "Stopping auto-skip after $consecutivePlaybackErrors consecutive playback error(s)")
        pause()
    }
}
```

#### Step-by-Step Cascade:
1. **Track 0 Fails**: If `startIndex` stream extraction fails (or as soon as Track 0 finishes), ExoPlayer encounters the raw web watch URL. `onPlayerError` fires, increments `consecutivePlaybackErrors` to `1`, and calls `seekToNextMediaItem()`, `prepare()`, `play()`.
2. **Track 1 Fails Immediately**: Track 1's `MediaItem` in ExoPlayer's timeline is still pointing to `https://www.youtube.com/watch?v=...` because background extraction (`resolveRemainingInBackground`) has not finished replacing it via `replaceMediaItem(1, ...)`. Track 1 fails instantly.
3. **Track 2 Fails Immediately**: `onPlayerError` fires again, increments `consecutivePlaybackErrors` to `2`, and calls `seekToNextMediaItem()`. Track 2 fails instantly.
4. **Playback Halts**: `consecutivePlaybackErrors` exceeds `MAX_CONSECUTIVE_PLAYBACK_ERRORS` (2), triggering `pause()`.
5. **UI Impact**: The UI rapidly steps through 2-3 tracks in under a second and stops, making Cloud Nine appear completely broken.

### 1.5 Extractor Latency & Pre-flight Bottlenecks

In `YouTubeExtractor.kt`:
* **Single Active Endpoint**: Piped extraction relies on a single primary endpoint (`https://pipedapi.wireway.ch`). If this endpoint rate-limits, errors out, or experiences high latency, stream extraction fails or stalls.
* **Pre-flight Check Overhead**: `verifyStreamUrl()` performs a synchronous HTTP `GET` with `Range: bytes=0-1023` for every candidate stream URL using a 15-second connect/read timeout client. If endpoints are sluggish, resolving a single track can take several seconds.
* **Silent Fallback**: When extraction fails, `resolveSongForPlayback()` catches the exception and returns the `Song` object unmodified (with `mediaUri` still set to the web watch URL), guaranteeing an ExoPlayer error.

## Part 2: The Solution & Fix Blueprint

To fix the Cloud Nine playback bug permanently and provide smooth cloud streaming, the following architectural enhancements are required.

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           UI Layer (Screen / ViewModel)                 │
│  User taps "Play All" on Cloud Nine -> PlayerViewModel.playQueue()      │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                       MediaControllerManager                            │
│ 1. Intercept cloud-only songs (isDownloaded == false).                  │
│ 2. Pre-resolve active track + buffer next track before ExoPlayer queue. │
│ 3. Use Media3 ResolvingMediaSource or Async Stream Resolver.            │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                          YouTubeExtractor                               │
│ 1. Query Piped / Invidious clusters with resilient round-robin.        │
│ 2. Cache direct Google Video CDN URLs (indexed by youtubeId + TTL).     │
│ 3. Fast pre-flight check (3s timeout).                                  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                       PlaybackService (ExoPlayer)                       │
│ 1. Receives MediaItems with DIRECT playable CDN URLs only.              │
│ 2. Prevents auto-skip cascade on unresolved MediaItems.                 │
│ 3. Handles track transitions by resolving next track just-in-time.      │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Architecture Blueprint & Implementation Steps

#### Step 1: Implement Media3 `ResolvingMediaSource` or Pre-Fetch Middleware
Instead of setting raw watch URLs directly into ExoPlayer `MediaItem`s:
* Use Jetpack Media3's built-in `ResolvingMediaSource.Factory` in `PlaybackService`, or implement an asynchronous Queue Resolver in `MediaControllerManager`.
* Ensure no `MediaItem` is submitted to ExoPlayer's timeline with a web watch URL (`https://www.youtube.com/watch?v=...` or `https://youtu.be/...`).

#### Step 2: Stream URL Caching Mechanism
Google Video CDN URLs contain an `expire=<timestamp>` parameter (typically valid for 6 hours).
* Implement an in-memory cache in `YouTubeExtractor`:
  ```kotlin
  data class CachedStream(
      val url: String,
      val expiresAtMs: Long
  )
  private val streamCache = ConcurrentHashMap<String, CachedStream>()
  ```
* Before making network requests to Piped/Invidious, check if a valid, non-expired CDN URL exists in `streamCache` for `youtubeId`.

#### Step 3: Sequential Just-In-Time Queue Resolution in `MediaControllerManager`
Modify `playQueueProgressively`:
* **Current Track ($N$)**: Must be resolved before calling `player.setMediaItems()`.
* **Next Track ($N+1$)**: Resolve track $N+1$ immediately after starting track $N$, ensuring ExoPlayer's pre-buffering mechanism receives a valid CDN URL.
* **On Track Transition (`onMediaItemTransition`)**: Trigger resolution for track $N+1$ dynamically as playback moves to track $N$.

#### Step 4: Refactor `PlaybackService.kt` Error Guard
Update `onPlayerError` in `PlaybackService.kt`:
* Check if `error.cause` is an `UnrecognizedInputFormatException` on a non-downloaded track.
* Instead of immediately calling `seekToNextMediaItem()`, trigger an on-the-fly resolution retry or pause playback gracefully with a user-facing notification ("Unable to stream track").

#### Step 5: Extractor Resiliency & Fallback Enhancement
In `YouTubeExtractor.kt`:
* Reduce `directoryLookupClient` and pre-flight timeouts from 15s to 3s.
* Expand `PIPED_ENDPOINTS` with additional verified mirrors.
* Ensure failure in `resolveSongForPlayback()` throws or returns a explicit unplayable state rather than silently passing raw web URLs to ExoPlayer.

## Summary of File Responsibilities & Required Modifications

| File Path | Current Issue | Proposed Fix |
| :--- | :--- | :--- |
| `playback/MediaControllerManager.kt` | Passes unresolved web watch URLs for queue items `!= startIndex` to ExoPlayer. | Resolve track $N$ and track $N+1$ before loading timeline; update `onMediaItemTransition` for just-in-time resolution. |
| `playback/PlaybackService.kt` | Rapidly skips up to 2 tracks on `onPlayerError` when encountering web watch URLs. | Handle stream resolution errors gracefully; prevent rapid skip loop on unextracted media URIs. |
| `data/youtube/YouTubeExtractor.kt` | Single Piped endpoint reliance; 15s timeout delays; no stream URL caching. | Add stream URL caching with TTL; optimize timeouts to 3s; implement multi-endpoint round-robin. |
| `data/repository/MusicRepository.kt` | `CLOUD_NINE_NAME` returns all undownloaded songs with raw web URLs. | Operational source of truth (no structural schema changes needed). |
